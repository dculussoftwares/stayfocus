## Context
v5 Family and Child's phone show the child's usage per hour (`HourTicks`, `DotGrid`) and "{model} · Android {version}" (prototype 196, 203, 343, 350). The child status report (M8-02, `ChildStatusRepository`) sends model, battery, current app and today's total/app list, but no hourly buckets or OS version.

## Scope
- Kids reporter: add `osVersion` (`Build.VERSION.RELEASE`) to the status doc, and today's 24 hourly buckets (`hourly: [Int × 24]`, minutes, from the `:core:usage` hourly aggregation) to the daily usage doc, with the same report cadence and size limits as today.
- `firebase/firestore.rules`: allow and validate the new fields (types, list length 24, each 0–60, string length cap); emulator tests in `firebase/rules-tests` for valid and invalid writes.
- Parent side: `LinkedDevice` gains `osVersion: String?` (from the status doc) and `hourlyMins: List<Int>?` (from today's daily usage doc, read by the same mapping that fills `todayMins`); both null until the child reports them, so older Kids builds keep working.
- The buckets go in the daily usage doc (per-day data, next to `totalMins`), not the status doc; V5_SPEC §6 says the same.
- Update `docs/IMPLEMENTATION_PLAN.md` §7 (Firestore data model) and the Data safety notes if the collected data description changes (it shouldn't: usage per app is already declared; say so in the PR).

## Acceptance criteria
- [ ] Unit tests for the reporter mapping and the parent mapping (missing fields → null).
- [ ] Rules emulator tests pass for the new fields, and an oversized/invalid list is rejected.
- [ ] A parent on this build shows nothing new for a child on the previous Kids build (no crash, fields null).
