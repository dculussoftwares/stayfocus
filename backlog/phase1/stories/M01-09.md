## Context
Tabs: Home · Block · Devices · Insights. Account opens from the avatar on Home. The tab bar shows on the tabs and also on Remote device and Account (prototype `showNav`).

## Scope
- Type-safe `@Serializable` routes: `Onboarding` graph (Welcome, SignIn, Permissions) and `Main` graph (Home, Block, Devices, Insights, Account, BlockWizard(target, prefill), LinkAdd, LinkScan, LinkConfirm(token), RemoteDevice(deviceId)).
- Each feature module exposes `NavGraphBuilder.xxxScreen(...)` and `NavController.navigateToXxx()`; `:app` assembles them. Features never import each other.
- A custom floating tab bar (r24) with mono labels and icons. The active tab is a lime pill with ink content. Tab state is saved and restored, and reselecting a tab pops to its root.
- `AppStartViewModel` picks the start graph from the `onboardingComplete` flag (stub returning `false`, so DataStore can be wired in M1-11).
- Placeholder screens with titles for every route, using the M1-06 enter transition.

## Acceptance criteria
- [ ] UI test: switching tabs keeps scroll state; back from a non-Home tab goes to Home; back from Home exits.
- [ ] The tab bar is visible exactly on Home/Block/Devices/Insights/RemoteDevice/Account.
- [ ] Deep-link-ready routes compile with arguments (no string routes).
