## Context
Firebase is needed from M6 on. Every cloud resource must come from Terraform (HCP Terraform state), applied only by GitHub Actions. This story builds the pipeline and an empty dev environment; later stories add resources milestone by milestone.

## Scope
- `infra/firebase/` root module: `versions.tf` (google + google-beta providers), `cloud {}` block that uses `TF_CLOUD_ORGANIZATION` / `TF_WORKSPACE`, `variables.tf` (`project_id`, `region`, `env`), and `main.tf` that enables the base APIs (`serviceusage`, `cloudresourcemanager`, `iam`) with `google_project_service`. `firebase.googleapis.com` is left to M6-01: enabling it with `serviceUsageAdmin` alone returned 403 on the first apply.
- `infra/bootstrap/` root module: the one-time foundation: GCP project(s) `stayfocus-dev` (and later `-prod`), billing link, a Workload Identity Federation pool + provider for `dculussoftwares/stayfocus`, and a deploy service account with least-privilege roles. Applied by a `workflow_dispatch` job (`infra-bootstrap.yml`) using a temporary bootstrap credential secret that is deleted after the first run, as documented in `docs/INFRASTRUCTURE.md`.
- `.github/workflows/infra-firebase.yml`: `terraform fmt -check`, `validate`, and `plan` on PRs touching `infra/firebase/**` (plan posted as a PR comment); `apply` on merge to `main` with GitHub Environment `dev` protection. Auth to GCP via `google-github-actions/auth` (WIF, no keys). HCP Terraform workspace `stayfocus-firebase-dev` in **local execution mode** (state only).
- `docs/INFRASTRUCTURE.md` section "Firebase/GCP": secrets and variables list, bootstrap steps, and how forks point at their own project.

## Acceptance criteria
- [ ] Merging a no-op change to `infra/firebase` runs apply successfully from Actions.
- [ ] No service-account JSON key exists after bootstrap (checked with `gcloud iam service-accounts keys list`).
- [ ] `terraform plan` on `main` shows no changes.

## Out of scope
Firebase products (M6-01, M7-01, M7-02, M9-03), the prod environment (M10-04).
