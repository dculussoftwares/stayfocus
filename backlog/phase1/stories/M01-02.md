## Context
Agents work in parallel and every change goes through a PR reviewed by CodeRabbit. CI is the automated half of that gate: it must catch formatting, static-analysis, test, coverage and build problems before review. The Definition of done (plan §4) runs here.

## Scope
- **Tooling**
  - Spotless with ktlint plus the Compose ktlint rules (`io.nlopez.compose.rules`), and an `.editorconfig`.
  - detekt with a committed `config/detekt/detekt.yml` that is Compose-friendly (allow `@Composable` naming, raise LongParameterList for composables), and an empty baseline.
  - Android Lint with `abortOnError = true`, `checkDependencies = true`, and `warningsAsErrors` for the Play-relevant checks.
  - **Kover** for coverage across modules, with a minimum line coverage: 80% for `:core:model` and `:core:blocking` logic, 60% overall (raised later).
  - **Roborazzi** screenshot tests: verify against committed baselines in CI; record locally.
- **`.github/workflows/ci.yml`** on `pull_request` and `push` to `main`. JDK 17 (temurin), `gradle/actions/setup-gradle` with cache and configuration cache, `concurrency` cancels superseded runs. Jobs run in parallel:
  - `static-analysis`: `spotlessCheck detekt lint`, uploading SARIF from detekt and lint so findings show in the PR (code scanning).
  - `unit-tests`: `testDebugUnitTest` (JVM + Robolectric) + `koverXmlReport koverVerify`; JUnit XML published as a check (e.g. `mikepenz/action-junit-report`); a coverage summary posted on the PR.
  - `screenshot-tests`: `verifyRoborazziDebug`; diff images uploaded as artifacts on failure.
  - `build`: `assembleDebug` for `:app` and `:kids` without `google-services.json`; APKs uploaded as artifacts (7-day retention).
  - `pre-commit`: `pre-commit run --all-files` (config from M1-14; skipped until that story lands).
  - `ci-pass`: an aggregate job that `needs` all of the above and fails if any failed or was cancelled. **This is the single required status check** (M1-12).
- Third-party actions pinned to commit SHAs, minimal `permissions`, no secrets needed (fork PRs work).
- `.github/pull_request_template.md` (`Closes #`, What changed / How tested / Acceptance criteria / Pending manual checks / Follow-ups, matching Prompt B) and `.github/ISSUE_TEMPLATE/story.md` that mirrors the story format of this backlog.
- `./gradlew ciCheck`: an aggregate task that runs locally exactly what the CI jobs run. Document it in `CLAUDE.md` and use it as the Definition-of-done command.

## Acceptance criteria
- [ ] A PR with a ktlint violation, a detekt issue, a failing unit test, coverage below the threshold, or a changed screenshot fails the matching job and `ci-pass`.
- [ ] A clean PR passes in under ~12 minutes with a warm cache; test results and coverage are visible on the PR.
- [ ] `./gradlew ciCheck` locally matches CI.

## Out of scope
Pre-commit hooks (M1-14), security scanning (M1-15), instrumented/E2E tests (M1-16), release builds (M10-03).
