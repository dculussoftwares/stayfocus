## Scope
- `UsageAccess.isGranted()` via `AppOpsManager.unsafeCheckOpNoThrow(OPSTR_GET_USAGE_STATS)` (with the API 26–28 equivalent).
- `UsageStatsDataSource.dayUsage(date): DayUsage` from `queryEvents`:
  - App-level foreground time: track the set of resumed activities per pkg (`ACTIVITY_RESUMED`/`ACTIVITY_PAUSED` on 29+, `MOVE_TO_FOREGROUND`/`BACKGROUND` on 26–28). Clip sessions at day/hour boundaries. Close open sessions at `SCREEN_NON_INTERACTIVE`, `DEVICE_SHUTDOWN` or the query end.
  - Opens: the pkg becomes foreground and differs from the previous foreground pkg.
  - Unlocks: `KEYGUARD_HIDDEN` count (API 28+). On API 26–27 use `SCREEN_INTERACTIVE` as the fallback and document it.
  - Hourly buckets (24) for time and unlocks. "First app after unlock" counts per pkg (used by the Insights Unlocks tab).
  - Exclude own packages, launchers and system UI from totals.
- Wrap `UsageEvents` behind a `RawUsageEvent` list so the logic is testable on the JVM.

## Acceptance criteria
- [ ] ≥ 20 unit tests with synthetic event streams (overlapping activities, midnight crossing, missing pause, screen off).
- [ ] On a real device, today's total is within ±5% of Digital Wellbeing (screenshot comparison in the PR).
