## Context
Rule: **all resources are created only through Terraform applied by GitHub Actions** (see `docs/INFRASTRUCTURE.md`). `infra/github` already manages the backlog (labels, milestones, issues). This story adds the repository's own settings and turns the review process into enforced rules: every change reaches `main` through a PR that **CodeRabbit** approved and CI passed.

## Scope
- Credentials: `GITHUB_TOKEN` can't change repo settings. Add *Repository → Administration* and *Pages* permissions to the `stayfocus-automation` GitHub App (docs/INFRASTRUCTURE.md, bootstrap step 3), and use an App token for the Terraform GitHub provider in the apply job. Plans keep using `GITHUB_TOKEN` with read access.
- In `infra/github`: import the existing repo as `github_repository` (description, topics, `has_issues`, `has_projects`, merge settings: squash only, delete branch on merge, allow auto-merge). Use an `import` block, not a manual import.
- A `github_repository_ruleset` on `main`:
  - pull request required; `required_approving_review_count = var.required_approvals` (default 1, satisfied by CodeRabbit's approval); stale approvals dismissed on push; **all review threads must be resolved**;
  - required status checks: `ci-pass` (the M1-02 aggregate of static analysis, unit tests, screenshots, build, pre-commit and later instrumented tests), plus CodeRabbit's status check if it publishes one (check the name on a real PR);
  - linear history, no force pushes, no deletion; no bypass actors except the org admin role for emergencies.
- **Verify** on a test PR that CodeRabbit's approval counts toward the required review. If GitHub doesn't count it, set `required_approvals = 0` and make CodeRabbit's status check required instead. Record which mechanism is used in `docs/INFRASTRUCTURE.md`.
- The `.github/workflows/backlog.yml` plan/apply flow covers these resources.

## Acceptance criteria
- [ ] A PR changing `infra/github` shows a Terraform plan as a PR comment; merging applies it.
- [ ] After apply: a direct push to `main` is rejected; a PR can't merge while CodeRabbit has requested changes, a thread is unresolved or `ci-pass` is red; it merges once CodeRabbit approves and CI is green.
- [ ] No settings were changed through the GitHub UI (the plan shows no drift).
