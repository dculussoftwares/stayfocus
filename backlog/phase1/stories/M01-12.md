## Context
Rule: **all resources are created only through Terraform applied by GitHub Actions** (see `docs/INFRASTRUCTURE.md`). `infra/github` already manages the backlog (labels, milestones, issues). This story adds the repository's own settings. Work lands **directly on `main`** (no PRs), so the rules protect `main`'s history rather than require reviews.

## Scope
- Credentials: `GITHUB_TOKEN` can't change repo settings. Add *Repository → Administration* and *Pages* permissions to the `stayfocus-automation` GitHub App (docs/INFRASTRUCTURE.md, bootstrap step 3), and use an App token for the Terraform GitHub provider in the apply job.
- In `infra/github`: import the existing repo as `github_repository` (description, topics, `has_issues`, `has_projects`, merge settings: squash only, delete branch on merge for outside-contributor PRs). Use an `import` block, not a manual import.
- A `github_repository_ruleset` on `main` that **allows direct pushes** by maintainers and agents, but blocks force pushes and branch deletion and requires linear history. Outside contributors (forks) still go through PRs with the `build` check.
- Variable `require_pull_requests` (default `false`). Setting it to `true` switches `main` to PR-only, with `required_approvals` and the `build` check, if the team later wants reviews.
- The `.github/workflows/backlog.yml` apply flow covers these resources.

## Acceptance criteria
- [ ] Merging a change to `infra/github` into `main` applies it from Actions.
- [ ] A normal push to `main` works; a force push and a branch deletion are rejected after apply.
- [ ] No settings were changed through the GitHub UI (the next run shows no drift).
