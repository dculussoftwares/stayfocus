## Context
Rule: **all resources are created only through Terraform applied by GitHub Actions** (see `docs/INFRASTRUCTURE.md`). `infra/github` already manages the backlog (labels, milestones, issues). This story adds the repository's own settings.

## Scope
- Credentials: `GITHUB_TOKEN` can't change repo settings. Add *Repository → Administration* and *Pages* permissions to the `stayfocus-automation` GitHub App (docs/INFRASTRUCTURE.md, bootstrap step 3), and use an App token for the Terraform GitHub provider in the apply job. Plans keep using `GITHUB_TOKEN` with read access.
- In `infra/github`: import the existing repo as `github_repository` (description, topics, `has_issues`, `has_projects`, merge settings: squash only, delete branch on merge). Use an `import` block, not a manual import.
- A `github_repository_ruleset` (or branch protection) on `main`: PRs required, 1 approval, required status check `build` from M1-02, linear history, no force pushes.
- The `.github/workflows/backlog.yml` plan/apply flow must cover these resources.

## Acceptance criteria
- [ ] A PR changing `infra/github` shows a Terraform plan as a PR comment; merging applies it.
- [ ] Pushing directly to `main` is rejected after apply.
- [ ] No settings were changed through the GitHub UI (the plan shows no drift).
