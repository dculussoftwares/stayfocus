## Context
Plan §9: Functions exist only for the 5 cases listed there. Each one must be safe by default, because a callable is reachable from the internet.

## Scope
- `firebase/functions`: TypeScript, Node LTS, 2nd-gen Functions SDK, ESLint, Jest, Firebase Admin SDK, an emulator config (`firebase.json`) for **local and CI testing only**. Deploys never use the Firebase CLI.
- Security baseline, shared by every function (a `secureCallable()` wrapper):
  - `enforceAppCheck: true` and `consumeAppCheckToken` for one-shot operations (link claim/approve);
  - `request.auth` required, with the caller's role checked in code (parent uid vs `childUid`);
  - input validated with `zod`, with typed `HttpsError`s and no internal details in messages;
  - per-uid rate limiting (a Firestore counter doc, e.g. max 10 link claims per hour);
  - structured logs without personal data.
- Terraform deploy: build and zip in Actions → `google_storage_bucket_object` (source hash in the name) → `google_cloudfunctions2_function` per function.
  - **One runtime service account per function** with least-privilege roles.
  - Callables: the Cloud Run invoker is public, because the Functions framework checks auth itself. Event triggers: no public invoker.
  - Required APIs: `cloudfunctions`, `cloudbuild`, `run`, `eventarc`, `artifactregistry`.
- A sample `ping` callable to prove the pipeline (remove it once a real function exists).

## Acceptance criteria
- [ ] A merged PR changing function code redeploys only that function.
- [ ] The CI job runs Jest against the emulators; the wrapper has tests for a missing auth, a missing App Check token, bad input and the rate limit.
