## Context
`notifyParent` is the only event-triggered Function. Sending FCM needs server credentials, which must never ship in an app.

## Scope
- Kids block screen extra action: "Ask {parent} for more time" → 15 / 30 / 60 min → create `requests/{id}` → "Request sent" waiting state.
- Parent app registers its FCM token in `users/{uid}/fcmTokens/{token}` (refreshes it; deletes it on sign-out).
- Function `notifyParent`: a Firestore `onDocumentCreated` trigger on `users/{uid}/devices/{id}/requests/{rid}` (and on `alerts` in M8-06). It builds the notification server-side from trusted fields only (it never forwards free text from the child unescaped), sends to all parent tokens and prunes invalid tokens. Terraform adds the Eventarc trigger, enables `fcm.googleapis.com`, and grants its own service account only `datastore.user` + FCM send. A shared `notify` module is reused by `unlinkDevice`.
- Parent notification actions Approve 15 / 30 / 60 and Deny: a `BroadcastReceiver` updates the request decision through Firestore (rules allow only the decision fields) and writes the `APPROVE_REQUEST`/`DENY_REQUEST` command.
- In-app: the amber card on Remote, and a badge on Devices.
- The child applies `APPROVE_REQUEST` as a `TemporaryAllowance(pkg, now + mins)`. Toasts: "Approved {label} of {app}" / "Request denied".

## Acceptance criteria
- [ ] An emulator test for `notifyParent` (FCM mocked), including invalid-token pruning.
- [ ] End-to-end on dev from both the notification and the in-app card in < 10 s; the allowance expires correctly.
