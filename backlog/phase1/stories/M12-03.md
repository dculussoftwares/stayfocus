## Context
v5 Child's phone has an ink tile "Lock all apps" / "Calls still work" that toggles to "Unlock apps" / "Everything is locked now" (prototype 370, 677). No such command exists (`CommandType` has per-app block, focus, requests, sync, remind). Focus sessions block everything for N minutes; "Lock all apps" is the same lock without an end time.

## Scope
- `CommandType.LOCK_ALL` and `UNLOCK_ALL` (`RemoteCommand` objects, empty payload); allow them in `firestore.rules` with emulator tests.
- Kids `ParentCommandHandlers`: persist an `allLocked` flag; the engine blocks every app except the phone/dialer, SMS, the launcher, system settings needed for emergencies, and Stay Focused Kids itself (reuse the focus-session allow list). Survives reboot and process death like focus does. Unlock clears it. Report `allLocked` in the status doc so the parent sees the state.
- Parent: `LinkedDevice.allLocked: Boolean`; `RemoteDeviceViewModel` actions `lockAll()` / `unlockAll()` with the shipped offline/failed delivery handling (no UI change here; M12-15 adds the tile).
- `docs/IMPLEMENTATION_PLAN.md` §7 command list updated.

## Acceptance criteria
- [ ] Unit tests: handler sets/clears the flag; rule evaluator blocks every app except the allow list while locked; state restored after restart.
- [ ] Rules emulator tests for both command types (parent may send, child may not create).
- [ ] Manual check (second phone) recorded in `docs/qa/pending-manual-checks.md`: lock, try apps, call still works, unlock.
