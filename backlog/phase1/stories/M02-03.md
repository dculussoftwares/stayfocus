## Context
Shown on top of a blocked app. The design is the prototype's "Kids: Blocked overlay" screen (status bar `#2A120E`), reused for self-blocking without the "Ask for more time" part.

## Scope
- `BlockActivity`: `excludeFromRecents`, its own `taskAffinity`, `singleInstance`/`singleTask`. Shows the app icon + "{App} · LOCKED", a reason line per `BlockReason`, a live countdown to reopen (`mmss`/`hms`) or "until HH:mm" / no countdown for manual locks, and a primary "Go to home screen" button. Back also goes home.
- Auto-finishes when the decision turns to Allow (re-evaluated each second while visible).
- An `extraActions` slot (used by Kids in M8-05) that is hidden in `:app`.
- `BlockScreenLauncher.show(pkg, decision)`: `performGlobalAction(GLOBAL_ACTION_HOME)` then `startActivity(NEW_TASK)`. **Verify background-activity-launch rules on API 29, 34, 35 and 36.** If the launch is blocked, fall back to a `TYPE_ACCESSIBILITY_OVERLAY` window added from the service. Document which path each API level uses.

## Acceptance criteria
- [ ] The block screen appears within 500 ms when a blocked app opens, on API 26 and API 36 (screen recording attached to the PR).
- [ ] It can't be dismissed into the blocked app with back, recents or home + reopen.
- [ ] Reason copy is in `strings.xml` and reviewed against the prototype.
