## Context
This uses a Function so the deletion is complete even if the app crashes halfway (Play's account-deletion requirement).

## Scope
- Callable `deleteAccount` (M7-02 secure wrapper; the caller must be the signed-in, non-anonymous user, and their auth token must be less than 5 minutes old, `auth_time`): it recursively deletes `users/{uid}` (`firestore.recursiveDelete`: devices and their subtrees, fcmTokens), deletes `linkTokens` claimed by the uid, then deletes the Auth user. Linked children notice their device doc is gone and reset (M7-09).
- Client: a confirm sheet → re-authenticate if the sign-in is older than 5 minutes → call → wipe local Room/DataStore account data → toast "Account and all data deleted." → Welcome.

## Acceptance criteria
- [ ] An emulator test proves no documents remain for the user and that a stale token is rejected.
- [ ] Manual end-to-end test on dev.
